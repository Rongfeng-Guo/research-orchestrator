## 3. 接入 OpenCode Go key 的结果

本轮临时使用用户提供的 OpenCode Go key，只放在进程环境变量里，没有写入文件。

先修了一个关键环境变量优先级问题：

- `src/utils/env_config.py`
- `tests/test_env_config.py`

之前 `.env.local` 会覆盖命令行临时传入的 `OPENAI_API_KEY` / `OPENAI_BASE_URL`，导致实际请求没有走 OpenCode Go。现在规则是：

1. 进程环境变量优先级最高；
2. `.env.local` 覆盖 `.env`；
3. `.env` 是默认配置。

验证结果：

- `OPENAI_BASE_URL=https://opencode.ai/zen/go/v1`
- `OPENAI_MODEL=qwen3.5-plus`
- 实际请求已命中 `https://opencode.ai/zen/go/v1/chat/completions`

同时发现：

- `qwen3.5-plus` 可正常返回；
- `mimo-v2.5` 也可正常返回；
- `deepseek-v4-flash` / `kimi-k2.6` 在极小测试中出现空 content；
- OpenCode Go key 后续开始返回 429 / insufficient_quota，说明额度基本耗尽。

## 4. 新增 keyless real-search fallback，但发现搜索相关性不足

更新：

- `src/tools/web_search.py`
- `tests/test_web_search_duckduckgo.py`

新增两个无需搜索 API key 的真实搜索后端：

- `duckduckgo`
- `bing_html`

本机网络下：

- DuckDuckGo HTML 请求超时；
- Bing HTML 可返回真实 URL，但搜索质量明显不稳定；
- 在 AI law / Copilot / SMR 等 query 上，Bing HTML 经常返回泛化、中文百科、知乎或完全跑偏结果。

因此，当前结论不是“keyless search 可以替代 SerpAPI/Bing API”，而是：

> keyless HTML search 适合管线探针，但不能作为 CCF-A 主实验的检索后端。

## 7. 修复执行预算和失败样本统计

更新：

- `src/agents/researcher.py`
- `src/orchestrator/agent_pool.py`
- `src/core/runner.py`
- `configs/real_evidence_fast.yaml`
- `tests/test_search_policy.py`

问题：

- 配置里有 `planner.max_search_rounds_per_subagent`；
- 但 ResearcherAgent 实际没有强制工具调用预算；
- 模型可以在同一轮一次性发出多个 `web_search` tool calls。

现在新增：

- `researcher.max_tool_calls_per_turn`
- `researcher.max_tool_calls_per_task`
- tool call truncation action log

另外修复：

- `scripts/build_search_cache.py`
- `tests/test_policy_cli_overrides.py`

之前模型/规划失败时，orchestrator 返回失败报告，但 `build_search_cache` 仍会把它写成 `status=success`。现在空失败报告会写成：

- `status=failed`
- `error=orchestrator_failed_or_empty_report`

这避免 quota/error 样本污染 success 统计。

## 9. 当前判断

项目现在已经具备：

- 可复现 query bank；
- train/heldout split；
- real-evidence runner；
- mock evidence gate；
- real source inventory gate；
- source relevance gate；
- citation quality gate；
- paper readiness audit；
- OpenCode Go 兼容接入验证；
- keyless search fallback 探针；
- 失败样本统计保护；
- 工具预算保护。

但距离 CCF-A 主实验还差最关键的一步：

> 需要可靠搜索后端，例如 SerpAPI / Bing Search API / Bocha / Metaso。Bing HTML fallback 可以用于 smoke，但当前不能支撑正式 claim。

下一步优先级：

1. 接入可靠搜索 API key；
2. 用 `real_evidence_bank_train_20260520.jsonl` 和 heldout 正式跑 runner；
3. 确认 `avg_source_relevance >= 0.15` 且 `avg_relevant_sources_per_success_query >= 2.0`；
4. 再训练 learned search policy；
5. 最后做 heuristic vs learned heldout head-to-head。
