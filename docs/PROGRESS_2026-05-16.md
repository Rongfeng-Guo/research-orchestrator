## 2. 今天定位到的真实断点

继续抽查自然 train split 的真实 cache 记录后，发现很多报告已经在尾部写了：

- `**参考文献**`

或者类似的参考来源列表，但正文没有任何 `[1]` 这种显式引用标记。

而 `SummarizerAgent` 原来的后处理逻辑虽然已经会：

- 识别是否有正文 citation
- 自动往正文补 `[1]`
- 自动追加 `## 参考来源`

但它有一个关键漏洞：

- `_split_reference_section()` 只能识别 `## 参考来源` 这类 Markdown heading；
- 对真实报告里常见的 `**参考文献**` 不生效；
- 于是尾部参考文献仍被当成“正文”的一部分；
- 正文检查又因为参考文献区里已经有 URL，误判为“正文已经有 citation”；
- 导致 inline citation 注入被跳过。

换句话说，之前不是没有 citation 修复逻辑，而是：

> **真实报告的参考文献样式绕开了这套逻辑。**

## 3. 今天做的代码修复

涉及文件：

- `src/agents/summarizer.py`
- `tests/test_summarizer_citations.py`

### 3.1 修复点

增强了 `SummarizerAgent._split_reference_section()` 的参考文献区识别能力。

现在不仅识别：

- `## 参考来源`
- `## References`

也能识别：

- `**参考文献**`
- `**参考来源**`
- `参考文献:`
- `参考来源:`
- 普通 `References / Sources`

这样一来，尾部参考文献区会先被正确切出去，再判断正文里是否已经有显式 citation。

结果就是：

- 尾部已有参考文献不再阻止正文 citation 注入；
- 现有参考文献区会被保留，不会重复追加一份新的来源列表；
- 正文里会稳定补上 `[1]` 风格显式引用。

### 3.2 新增回归测试

补了一条更接近真实失败样式的测试：

- 报告正文没有 citation；
- 尾部已经有 `**参考文献**` + URL；
- 之前这类报告不会补正文 citation；
- 现在会补。

## 5. 今天最重要的研究结论

今天最关键的结论不是“citation 终于高了”，而是我们把问题边界再次收窄了：

> **当前 citation 低，不一定说明 agent 没找到来源；很大一部分问题来自 final report 没把已有 grounded source 渲染成显式 citation。**

这意味着：

1. 之前很多 `citation` 很低的结果，不能简单解读成 search policy 没学到 grounding。
2. 当前最该优先修的是 `grounded source -> explicit citation` 链路。
3. 在这个链路修通之前，继续用 citation 指标判断 learned/heuristic 优劣，会混入明显的渲染噪声。

## 14. 继续推进：把 source inventory 和 citation quality 纳入门槛

- 重渲染后 `source_utilization` 看起来很高；

- 也就是说，系统不是“充分利用了多来源”，而是“单来源被反复引用”。

为了避免这个指标陷阱，今天继续补了 source/citation quality 层：

### 14.3 TrajectoryCollector 会从工具轨迹恢复 source inventory

更新：

- `src/evolution/collector.py`
- `scripts/build_search_cache.py`
- `tests/test_evidence_evaluation.py`

之前 `build_search_cache` 在有 `action_log` 时会优先使用结构化动作日志，可能丢掉 raw tool result 里的 `results/papers` source 细节。

现在：

1. `_flatten_task_actions()` 会同时保留 `action_log` 和 raw `trajectory`；
2. `TrajectoryCollector.collect()` 会从 raw tool result、`top_urls`、browser `tool_args.url` 中恢复 source inventory；
3. 恢复出的 sources 会和 `report.sources` 去重合并；
4. `source_count` 使用合并后的 source inventory。

这对下一轮 real-evidence cache 很关键，因为真实搜索通常会返回多条候选来源，不能只依赖 summarizer 最后保留下来的少数引用。

### 14.5 Citation injection 从“少量补标”升级为“分散补标”

继续更新：

- `src/agents/summarizer.py`
- `tests/test_summarizer_citations.py`

原先 citation surface 后处理最多补 3 个 inline markers。对长报告来说，这会造成一个尴尬结果：

- `citation_coverage` 有提升；
- 但 `citation_density` 仍偏低；
- 很多事实段落仍没有显式支撑。

现在 `_inject_inline_citation_markers()` 会：

1. 根据候选事实段落数量决定目标 citation 数；
2. 最多补 8 个 marker，避免过度刷引用；
3. 在长报告中分散位置，而不是只补最前几段；
4. 多 source 时循环使用 `[1] [2] [3] ...`。

重新 resurface 后，train split 变为：

- `avg_citation_coverage = 0.1150`
- `avg_citation_density = 0.2748`
- `avg_citation_quality_score = 0.6235`

heldout split 变为：

- `avg_citation_coverage = 0.1114`
- `avg_citation_density = 0.2686`
- `avg_citation_quality_score = 0.5559`

这次改动使 `citation_density_low` 风险消失，但没有也不应该绕过真实证据 gate：

- `mock_source_detected` 仍存在；
- `real_source_query_ratio = 0.0000`；
- `avg_real_sources_per_success_query = 0.0000`；

- 训练阶段仍会检查 real source、mock source、source inventory、citation quality。


这意味着接下来只要配置好真实 key，就可以直接运行：

```bash
python scripts/run_real_evidence_iteration.py
```

如果只想采集和分析、不训练：

如果只是 smoke/debug，才显式允许 mock：

```bash

```

但 `--allow-mock-evidence` 产物不能用于 headline claim。

- `tests/test_audit_paper_readiness.py`

这个脚本把 analysis JSON 和 training summary JSON 合并审计，输出：

- overall status: `PASS / BLOCKED`
- analysis-level checks
- training/headline checks
- failed checks
- next actions

默认检查项包括：

- `success_query_count >= 8`
- `browser_query_coverage >= 0.25`
- `nonzero_composite_query_ratio >= 0.50`
- `avg_citation_coverage >= 0.05`
- `avg_citation_density >= 0.20`
- `avg_citation_quality_score >= 0.20`
- `real_source_query_ratio >= 0.80`
- `mock_source_query_ratio <= 0.0`
- `avg_real_sources_per_success_query >= 2.0`
- `training_allowed == true`
- `headline_claim_ready == true`
- `training_status == trained`
