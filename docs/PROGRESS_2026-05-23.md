## 4. 当前最诚实的论文判断

现在可以更明确地区分两条 claim：

1. **Evidence-readiness claim 可以写**
   - 8-query benchmark 已经通过 source reality、source relevance、browser coverage、citation quality 等门控；
   - official-source-aware seeded retrieval + agent-side URL propagation + search/browser 两跳链路，在这个小型真实 benchmark 上已经闭环。

2. **Learned-policy superiority claim 还不能写**
   - 聚合均值略好，但 `+0.005` 太小；
   - fold-level mixed；
   - citation coverage 有轻微下降风险；
   - learned 有时像是学会了更早停止，而不是稳定学会了更好取证。

所以当前论文叙事应改成：

> 我们已经把 deep research agent 推到一个能通过 evidence-readiness gates 的真实小型 benchmark；learned policy 显示了成本下降和局部质量提升的潜力，但稳定优于 heuristic 仍需更大 no-leak heldout 支撑。

## 6. 下一步

下一步不建议再从这 8 条里过度榨结论。更优路线是：

1. 把 fast benchmark 从 8 条扩到 12-16 条；
2. 保持 query-level no-leak split；
3. 优先补法律、金融、能源之外的新 domain，避免 learned 只记住当前查询形态；
4. 增加一条针对 premature stopping 的训练/评测信号，例如：
   - 最低 browser follow-up 要求；
   - citation coverage 不下降约束；
   - 或把 source utilization 纳入 learned policy reward；
5. 等 cross-fold 的质量提升不再只靠 1-2 个 fold 拉均值，再考虑写 learned-vs-heuristic 主实验表。

当前项目已经从“能不能取到真来源”推进到“如何让 learned policy 不只是省 token，而是真正更会取证”。这是一个更窄、更干净，也更像论文问题的位置。

### 7.3 baseline table 与 SOTA 口径

为了避免只看 10 条造成偶然性，本轮继续用固定 `seed=42` 跑了 50 条 HotpotQA：

1. `closed_book_qa`
   - 不提供 HotpotQA context；
   - 只让同一个 LLM 根据自身知识直接回答短答案。
2. `context_qa`
   - 提供 HotpotQA distractor context；
   - 不走完整 agent；
   - 不调用外部搜索。

运行产物：

- `outputs/hotpotqa_public_closedbook_seed42_n50/HotpotQA_DeepResearch_Evaluation_20260523_145916.json`
- `outputs/hotpotqa_public_contextqa_seed42_n50/HotpotQA_DeepResearch_Evaluation_20260523_150055.json`

结果：

| mode | n | EM | F1 | pass@1 | gold_entity_coverage |
|---|---:|---:|---:|---:|---:|
| `closed_book_qa` | 50 | 0.200 | 0.297 | 0.200 | 0.398 |
| `context_qa` | 50 | 0.600 | 0.669 | 0.600 | 0.878 |

随后又补了一个中间模式：

3. `context_agent`
   - 不走完整 planner/search/summarizer；
   - 但也不是单步回答；
   - 先抽取 evidence notes，再进行严格短答案抽取。

运行产物：

- `outputs/hotpotqa_public_contextagent_seed42_n50/HotpotQA_DeepResearch_Evaluation_20260523_160238.json`

结果：

| mode | n | EM | F1 | pass@1 | gold_entity_coverage |
|---|---:|---:|---:|---:|---:|
| `closed_book_qa` | 50 | 0.200 | 0.297 | 0.200 | 0.398 |
| `context_qa` | 50 | 0.600 | 0.669 | 0.600 | 0.878 |
| `context_agent` | 50 | 0.660 | 0.798 | 0.660 | 0.895 |

继续优化后，`context_agent` 增加了三处变化：

- context QA 统一 `temperature=0.0`；
- evidence notes 阶段给更大输出预算，answer extraction 阶段压成短输出；
- 增加 verifier pass：根据 question / context / notes / draft answer 再校正一次最短答案；
- 增加少量不看 gold 的 HotpotQA 短答案规范化。

固定 `seed=42` 的 100 条结果逐步提升为：

| run | n | EM | F1 | pass@1 | 说明 |
|---|---:|---:|---:|---:|---|
| `context_agent_seed42_n100_v5_temp0` | 100 | 0.680 | 0.808 | 0.680 | 固定 temperature |
| `context_agent_seed42_n100_v7_verify` | 100 | 0.720 | 0.834 | 0.720 | 增加 verifier |
| `context_agent_seed42_n100_v8_norm` | 100 | 0.750 | 0.852 | 0.750 | 增加短答案规范化 |

随后用同一设置扩大到 200 条：

- `outputs/hotpotqa_public_contextagent_seed42_n200_v9_norm/HotpotQA_DeepResearch_Evaluation_20260523_180552.json`

结果：

| mode | n | EM | F1 | pass@1 | gold_entity_coverage |
|---|---:|---:|---:|---:|---:|
| `context_agent_v9` | 200 | 0.765 | 0.865 | 0.765 | 0.892 |

这个数值在当前固定 dev subset 上已经高过 HotpotQA 官方 distractor leaderboard 中 Beam Retrieval 的 Answer EM/F1：

- Beam Retrieval Answer EM: `72.69`
- Beam Retrieval Answer F1: `85.04`

但必须非常明确：这仍然不能写成“HotpotQA SOTA”。

原因：

1. 官方 leaderboard 是 blind test / 官方提交口径；
2. 当前结果是 `dev_distractor` 的 `seed=42, n=200` 子样本；
3. 我们只报告 answer EM/F1，没有 supporting fact EM/F1 和 joint EM/F1；
4. `context_agent` 使用的是给定 distractor context，不评估 fullwiki retrieval；
5. 短答案规范化是本地规则，需要在完整 dev set 上确认不会过拟合。

当前可以写的最强但诚实的说法是：

> On a fixed 200-example HotpotQA dev-distractor subset, our lightweight context-agent diagnostic exceeds the official leaderboard's Beam Retrieval answer EM/F1 numbers, but this is not an official SOTA claim because it is not evaluated on the blind test server and does not include supporting-fact or joint metrics.

为了对齐 HotpotQA 官方口径，本轮继续补了 supporting-fact / joint metrics：

这一步把结论进一步收紧了：

- Answer EM/F1 已经能在 dev subset 上接近甚至超过官方 Answer-only 数值；
- 但 supporting-fact exact match 很低；
- joint metrics 明显不够；
- 因此从 HotpotQA 完整官方口径看，当前离真正 SOTA 还差得很远。

换句话说，`context_agent` 已经是一个强 answer extractor / evidence consumer，但还不是强 supporting-fact selector。

更重要的是，HotpotQA 不是本文主 benchmark。它的价值在于：

- 验证 context-grounded evidence consumption 可以工作；
- 证明 closed-book 不够，context 确实显著提升；
- 证明一个轻量 evidence-agent 结构比单步 context QA 更好；
- 暴露完整 research agent 与 short-answer QA benchmark 的接口错配。

### 7.5 这个结果对科研路线的意义

这次 public benchmark smoke 很有价值，因为它把一个新的缺口暴露得很清楚：

> 我们现在的系统更像 open-ended evidence research agent，不是一个严格 obey provided context 的 multi-hop QA solver。

所以后续如果要用公开 benchmark 增强论文说服力，不能只是“下载 HotpotQA 然后跑全量”。现在 `context_qa` baseline 已经证明公开集可跑，下一步应该补的是 agent 侧的 context-grounded execution mode：

1. 关闭或弱化外部 search；
2. 把 dataset context 放进受控证据池；
3. 要求 planner/researcher 只从 context 中取证；
4. 增加短答案抽取器；
5. 对日期、别名、行政区后缀等做标准 normalize；
6. 下一步跑完整 dev_distractor 或官方 blind submission 口径，同时补 supporting-fact / joint metrics。

这条 public benchmark 不一定要成为论文主实验，但很适合作为外部 sanity check：证明我们的 evidence pipeline 不只在自建 official-source queries 上有效，或者反过来诚实说明它目前更适合 long-form research，而不是短答案 QA。
