# DeepResearch Agent 目标分层：项目、研究原型、CCF-A

日期：2026-05-15

这份文档回答一个比“下一步做什么”更根本的问题：

- 我们现在到底在做一个什么东西？
- 最终希望得到的是一个项目，还是一篇论文？
- 这条线有没有可能冲击 CCF-A 级别会议？

最短答案先写在前面：

> **当前最合理的定位，不是产品项目，也不是已经成型的顶会论文，而是一个正在收敛研究问题的 research prototype。**

---

## 1. 现在的真实目标是什么

如果只用一句话概括，我认为当前真实目标应该是：

> **把 deep research agent 里的局部搜索控制问题，做成一个可训练、可评测、可归因的研究对象。**

注意这里的关键词不是：

- 全功能 agent
- 最炫的多智能体系统
- 最复杂的 browser 环境

而是：

- `可训练`
- `可评测`
- `可归因`

这决定了我们现阶段的优先级必须是：

1. 把问题定义清楚。
2. 把实验链路做干净。
3. 把成功标准立住。

而不是不断往系统里叠模块。

---

## 2. 我们最终希望得到什么结果

### 2.1 最低层结果：一个像样的项目

最低层的成功，不是论文，而是一个扎实的研究型项目：

- 有完整的 deep research agent 框架；
- 有 `policy_trace -> cache -> train -> runtime -> eval` 闭环；
- 有可复现脚本；
- 有清晰文档；
- 有一条不乱试验的实验协议。

如果最终只做到这一步，它仍然是一个有价值的项目。因为它不是一个普通 demo，而是一个：

> **适合继续做 agentic search / deep research 学习实验的平台。**

这类项目对：

- 个人研究积累
- 组内继续接力
- 申请、面试、答辩展示

都已经有明显价值。

### 2.2 中层结果：一篇可信的研究论文

如果要从“项目”变成“论文”，就不能只证明：

- 跑通了；
- 接上了 learned policy；
- 某几个样本上分数高了一点。

必须至少证明：

1. 我们定义的问题是清楚的。
2. 我们的方法和已有工作有边界差异。
3. 我们的改进是稳定的，不是噪声。
4. 我们知道它为什么有效，或为什么失效。

对当前这条线来说，最像论文的主结论不是：

- “我们做了一个 deep research agent”

而是：

> **在 long-form deep research setting 中，budget-aware、citation-aware 的 learned search control 能改善 quality-cost frontier。**

### 2.3 高层结果：有机会冲击 CCF-A 的研究

如果要谈 CCF-A 级别，不是完全没可能，但门槛会高很多。

要达到那个层次，通常至少需要下面三类东西里占到两类以上：

1. **清晰而有辨识度的问题定义**
   - 不是泛泛的“agent 更强了”
   - 而是一个社区认可、边界清楚的问题

2. **方法贡献足够扎实**
   - 不是只把现有部件拼起来
   - 而是真正有方法设计上的新东西

3. **评测证据足够强**
   - 不只用内部题集
   - 不只用少量样本
   - 不只看单个指标

当前我们离第 3 点还明显不够。

---

## 3. 现在它更像项目，还是更像论文种子

我的判断是：

> **现在它首先是一个研究型项目；但如果问题继续收窄、实验继续变干净，它有机会长成论文种子。**

这里的关键不是“有没有工程量”，而是：

- 当前是否已经有顶会级别 claim

答案很明确：

- **现在还没有。**

因为当前我们还处在：

- data distribution 还不健康
- browser 正例还太少
- citation 还太弱
- 外部 benchmark 还没真正接进来

的阶段。

所以今天最准确的定位是：

> **研究原型，不是产品；论文种子，不是成熟顶会故事。**

---

## 4. 如果只把它当项目，最终标准是什么

如果最后这条线没长成顶会论文，它仍然可以以“高质量研究项目”的标准收尾。

项目版成功标准应该是：

1. 有一条完整实验闭环。
2. 有明确的基线和对照脚本。
3. 有可复现的 cache / train / eval 流程。
4. 有文档写清楚：
   - 做了什么
   - 为什么这样做
   - 哪些实验该做
   - 哪些实验不该做
5. 有至少一个清楚的负结果或正结果分析。

这类项目的价值在于：

- 它是“可继续研究”的基础设施；
- 它有方法意识，不是只堆工程；
- 它已经能体现研究判断力。

---

## 5. 如果想往 CCF-A 靠，缺什么

当前最明显的缺口，我认为有五个。

### 5.1 问题还需要再收窄

现在方向是对的，但 story 还偏大。

更适合冲击顶会的不是：

- Query Policy RL + Retriever Router + Summary State + Reward 全都做

而是：

- 只选一个非常清楚的切口，把它做深。

例如：

> budgeted, citation-aware local search control for long-form deep research

### 5.2 方法还不够“新”

现在最强的是：

- 系统整合
- 实验链路
- 研究 framing

但真正的方法 novelty 还不够硬。

如果最后只是：

- offline cache
- 线性 policy
- runtime 接入

那更像一个好 baseline，而不是顶会方法贡献。

### 5.3 评测证据还不够强

当前主要问题：

- 内部题集为主；
- 样本还小；
- citation 信号弱；
- browser 使用太少。

如果这些不补，论文就很难支撑强 claim。

### 5.4 归因还不够完整

顶会级别很怕一种情况：

- 指标变了；
- 但不知道为什么变。

我们现在已经开始解决这个问题，因为：

- 有 `policy_trace`
- 有 cache 分析
- 有训练前门控

但还不够。还需要更强的 failure mode analysis。

### 5.5 外部有效性还不够

如果最后只在仓库自己的 `ResearchBench` 上有效，那更像：

- internal research artifact

而不是：

- community-level result

要冲高层级，迟早得接更公开、更开放的评测环境。

---

## 6. 什么情况下，它有资格从“项目”升级成“论文候选”

我建议用下面这个门槛来判断。

### 可以升级成论文候选的信号

1. learned policy 在更稳的数据集上表现稳定。
2. `citation_coverage` 不再长期接近零。
3. learned 不再只是“多 search 少 browser”。
4. quality-cost tradeoff 能稳定复现。
5. 在不止一个题集/环境上成立。

只要这五条里拿下三到四条，它就开始像一篇真正的论文。

---

## 7. 什么情况下，才值得认真谈 CCF-A

如果未来真要往 CCF-A 方向冲，我认为至少要满足下面这几个条件。

### 条件 1：主 claim 非常锐利

不是“大而全 agent 系统”，而是一个可一眼说清的研究问题。

### 条件 2：方法贡献不是拼装

必须有至少一个别人不能轻易说成“工程整合”的点。

### 条件 3：实验非常硬

至少包括：

- 足够强的 baseline
- 足够清楚的 ablation
- 足够稳定的结果
- 足够诚实的 failure analysis

### 条件 4：外部 benchmark 或外部 setting 有说服力

否则很难证明这不是内部系统特例。

### 条件 5：论文故事非常克制

顶会不是看你做得多，而是看：

- 问题是否清楚
- 方法是否新
- 证据是否硬

现在我们距离这个标准，还有明显距离。

所以最诚实的说法应该是：

> **有潜力成为 CCF-A 方向上的早期种子，但现在还处在把问题做对、把证据做硬的阶段。**

---

## 8. 当前阶段最合理的目标分层

我建议把目标明确分成三层。

### P0：研究型项目完成度

目标：

- 把实验平台和链路做扎实

成功标准：

- cache / analysis / training / eval / docs 闭环稳定

### P1：论文候选

目标：

- 拿到一个清楚而可信的主结论

成功标准：

- learned policy 在质量-成本-citation 三者上有可重复优势

### P2：顶会候选

目标：

- 把这条线打磨成社区级问题 + 方法 + 证据

成功标准：

- 不是只“能跑”，而是真的“有研究贡献”

当前我们最应该盯住的是：

> **先把 P0 做扎实，再争取 P1；不要现在就按 P2 的叙事自我催眠。**

---

## 9. 最终判断

如果你问我现在到底该把它当什么，我的答案是：

> **现在它应该被当成一个高质量研究原型项目。**

如果你问我它有没有可能长成 CCF-A 方向的研究，我的答案是：

> **有可能，但前提不是继续堆系统，而是把问题收窄、方法做实、证据做硬。**

再直白一点：

- **现在：更像项目 + 论文种子**
- **未来：如果 quality-cost-citation 的主结论做出来，才开始像论文**
- **更远：如果外部评测、方法新意、稳定优势都补齐，才有资格认真谈 CCF-A**

---

## 10. 2026-05-15 实证更新：为什么它现在仍然不是 CCF-A 故事

今天我们已经把一轮更完整的证据链跑出来了：

1. 通过受控 `browser-positive` query 把组合 cache 的 `browser_step_ratio` 提到 `0.1214`。
2. 在门控允许后训练了 `artifacts/search_policy_20260515_v2.json`。
3. 在固定 `2` 题 benchmark 上重跑 `heuristic vs learned`。

如果只看“训练终于通过了”，很容易高估当前阶段。

但只要把完整事实放在一起，结论其实非常清楚：

- `training_allowed = true`
- `headline_claim_ready = false`
- learned `v2` 不再压没 `browser`
- 但 learned `v2` 也没有形成新的质量优势
- `citation_coverage` 仍然是 `0.0`
- 搜索/浏览依然运行在 `mock_mode: true`

所以最准确的判断不是：

- “我们已经证明 learned search policy 有效”

而是：

> **我们证明了：数据分布和门控标准足以显著改变 learned policy 的局部行为，但还没有证明它带来了社区级的质量收益。**

这正是“研究原型”和“顶会故事”之间的差别。

---

## 11. 这条线为什么仍然有科研潜力

虽然现在还远不够强，但它仍然值得继续做，不是因为“工程很多”，而是因为问题本身确实踩在一个活跃研究交叉点上：

1. `search / browser / stop` 这种局部控制，正好位于 search-RL、browsing agents、deep research 三条线的交叉处。
2. 当前相关工作很多在回答：
   - 搜索是否可学
   - 深研究 agent 如何评测
   - 检索/组织/浏览哪个环节是瓶颈
3. 但“citation-aware、budget-aware 的局部搜索控制”这个切口仍然有空间，只是必须非常克制地定义问题。

换句话说：

> **这条线的潜力不在于“我们也做了个 deep research agent”，而在于能否把局部搜索控制做成一个独立、可归因、可评测的问题。**

---

## 12. 哪种结果才会把它从“种子”推向“论文候选”

接下来如果想从 `P0/P1` 靠近更强论文候选，我认为至少要出现下面三类进展里的两类：

1. **自然数据上的稳定增益**
   - 不是只靠 `受控浏览` 增广
   - 而是在自然 query 上也能稳定触发合理 browser 行为

2. **citation 不再长期贴地**
   - 不要求一下子很高
   - 但不能继续长期停在 `0.0 ~ 0.01`

3. **对 heuristic 的明确优势**
   - 要么质量更高且成本不更差
   - 要么质量持平但成本显著下降

如果这三条仍然拿不下来，那么最合理的收口方式就是：

- 承认它是高质量 research prototype
- 把它沉淀成后续工作的实验平台

这依然是有价值的结果，只是不是顶会 claim。

---

## 13. 如果真要冲更高层级，story 应该怎么收窄

当前最危险的做法是把 story 写成：

- Query Policy RL
- Retriever Router
- Summary State
- Reward 设计
- Full-stack Deep Research Agent

这会直接把问题做散。

更可能走到高层级的写法，反而应该更窄：

> **Budgeted, Citation-Aware Local Search Control for Long-form Deep Research**

这个版本的好处是：

1. 问题边界清楚。
2. 能和泛化的 search-RL 区分开。
3. 能和 retrieval-only / browser-only / summarization-only 工作区分开。
4. 失败了也知道失败在哪。

---

## 14. 最新一句话判断

如果只问“有没有 CCF 水平潜力”，我的回答是：

> **有研究潜力，而且值得继续做；但当前最诚实的定位仍然是 research prototype / paper seed，而不是已经具备 CCF-A 说服力的结果。**

如果后面能拿到：

- 自然 browser-positive 数据
- 非零 citation 的稳定提升
- 对 heuristic 的可重复优势
- 外部 benchmark 上的结果

它才会真正开始从“项目”变成“论文候选”，再进一步才谈得上冲更高层级。
