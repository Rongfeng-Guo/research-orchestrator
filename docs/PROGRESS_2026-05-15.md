## 1. 今天推进了什么

### 1.1 新增 `search_cache` 分析脚本

新增：

- `scripts/analyze_search_cache.py`
- `tests/test_analyze_search_cache.py`

这个脚本解决的问题不是“多一个工具”，而是把之前靠人工观察的判断变成结构化输出。它现在会统一给出：

- record/query 数量
- success / failed
- step-level `search / browser / stop` 标签分布
- browser query coverage
- average composite / factual / citation
- risk flags
- per-query snapshot

意义：

- 以后不需要手工数 `browser` 样本；
- 能快速判断当前 cache 是否值得训练；
- 让“不要乱做实验”真正落到流程里。

### 1.2 新增训练前门控脚本

新增：

- `scripts/train_search_policy_iteration.py`
- `tests/test_train_search_policy_iteration.py`

这个脚本会在训练前先做 readiness check，默认门槛是：

- `num_success >= 8`
- `browser_step_ratio >= 0.10`
- `browser_query_coverage >= 0.25`

若不满足：

- 默认直接阻止训练；
- 只输出分析结果和阻止原因；
- 避免在明显失衡的数据上继续“试一版看看”。

这一步的核心不是自动化本身，而是把研究 hygiene 写成程序，而不是写在文档里没人执行。

## 5. 今天为什么没有继续训练

### 5.1 这一步的意义

这不是“失败”，恰恰相反，这是实验纪律第一次真正生效。

今天最重要的工程和研究进展之一，其实是：

> **系统现在已经可以阻止我们在明显不合格的数据上继续做没有归因价值的训练。**

如果今天继续重训，大概率只会得到另一版：

- 继续偏 `search`
- 几乎不学 `browser`
- 然后再拿一点噪声指标讲故事

这正是我们要避免的。

## 6. 今天最重要的 insight

昨天的 insight 是：

> learned policy 更像在学“多 search、少 browser”。

今天的新 insight 更进一步：

> **问题可能不只是 learned policy 学歪了，而是训练数据本身就几乎没有给它足够多的 browser 正例去学。**

这意味着下一步优先级应该调整为：

1. 不要急着再训；
2. 先提高 browser-positive data 的比例；
3. 再看 learned 是否还会继续压 browser。

这比直接调 learning rate、阈值、reward 都更有因果价值。

---

## 7. 下一步建议

今天之后，最合理的下一步已经很清楚：

## 12. 今天新增的核心 insight

截至这一轮，最关键的研究判断已经从：

- “要不要先补 browser 正例”

变成了：

- “补出来的 browser 正例，究竟是在修复局部行为，还是已经足够支撑论文式证据”

当前答案很明确：

> **只做受控 browser 增广，可以修复 policy collapse；但它本身还不能制造 citation gain，也不能制造 headline-level evidence。**

这也是为什么我们把门控分成了两层：

1. `training_allowed`
2. `headline_claim_ready`

如果不区分这两层，就会很容易犯一个研究上很危险的错误：

- 训练能跑通
- 行为看起来更合理
- 然后误以为已经拿到了论文结果

实际上，我们现在拿到的更像是：

- 一个有效的 bootstrap technique
- 一个更诚实的实验 hygiene 机制

而不是：

- 一个已经成立的主结论

---

## 13. 对“科研潜力”的最新判断

如果问题是：

- “这条线还值不值得继续做？”

我的答案是：

> **值得。因为它已经表现出一个真实可控的问题：局部搜索策略会塌缩，而数据分布和门控设计能显著改变这种塌缩。**

但如果问题是：

- “现在能不能当成 CCF-A 级故事来讲？”

答案仍然是否定的。原因不是想保守，而是证据确实还差关键几步：

1. `configs/aliyun_smoke.yaml` 里搜索/浏览仍是 `mock_mode: true`。
2. 当前 citation 仍然长期接近零。
3. 受控增广占比过高，组合 cache 里只有 `33.33%` query 有非零 composite。
4. `v2` learned 只是恢复到 heuristic 附近，还没有稳定超越 heuristic。

## 14. 下一步只应该做什么

现在最合理的下一步不是再训第三版，也不是改 reward，而是：

1. 专门收集一批**自然发生的 browser-positive query**。
2. 让这些 query 尽量来自非 `受控浏览` 域，而不是继续堆 synthetic control。
3. 在更大的固定 benchmark slice 上重跑 `heuristic vs learned`。
4. 只有当 `headline_claim_ready` 也转成 `true` 时，才开始认真讨论论文结论。

如果做不到第 1 条和第 2 条，那么这条线更适合被定义为：

> **高质量研究原型 + 论文种子**

而不是：

> **已经拿到强研究结论的项目**

- `natural browser-positive`

而应该叫：

- `natural browser-grounded`

也就是：

> **不只是开过 browser，而是 browser 后真的出现了 citation / grounding 信号。**

## 29. 为什么这次结果还不能支持论文级 claim

这次结果虽然是第一次真正 clean 的 held-out eval，但仍然只能支持非常克制的内部结论，原因至少有四个：

1. `headline_claim_ready` 仍然不成立  
   当前最核心的 citation 指标没有稳住。

2. 行为变化过少  
   `5/7` query 的 cost footprint 与 heuristic 相同，说明 learned 还没有展示出稳定的新策略。

3. 生成噪声仍然可能影响小幅分差  
   当前配置里的模型采样温度仍是 `0.2`，因此像 `+0.006` 这样的微小 composite 差值，不能直接当成稳健 policy gain。

4. 环境仍然是 `mock_mode`
   `configs/aliyun_smoke.yaml` 中 `tools.web_search.mock_mode: true`，所以即使 held-out 上有正结果，也仍然只是内部研究信号，不足以支持对外强 claim。

因此，今天最诚实的定位仍然是：

> **research prototype 有了第一次无泄漏 held-out 结果，但还没有形成值得对外讲的 headline。**

## 30. 现在真正该做什么

这次 held-out 对照跑完之后，下一步反而更清楚了。

这一轮 clean eval 之后，我们对方向的理解已经更聚焦了：

> **当前的主要问题不是“learned 会不会搜”，而是“learned 能不能把搜索和 browser 变成稳定的 grounding 增益”。**

## 34. 这对下一步研究意味着什么

现在“继续补 query”的方向已经不应该理解成：

- 再去找更多会开 browser 的自然题

而应该理解成两条更精确的工作线：

1. **数据线**
   - 用 `natural_researchbench_train_grounded_20260515.jsonl`
   - 和 `natural_researchbench_train_latent_grounded_20260515.jsonl`
   - 作为后续 rerun / replay / citation-fix 的自然训练 query bank

2. **机制线**
   - 重点研究 `browser -> grounded source -> explicit citation` 这条链路到底断在哪
   - 现在最可疑的环节已经不是 query 选择，而是 final report 的 citation surface form

这让我们的目标又收窄了一层：

> **下一阶段最值得做的，不是继续证明 learned 会不会开 browser，而是让已有 grounded evidence 更稳定地变成可计分、可追溯的显式 citation。**

如果后面这一条能被修通，再回到更大 natural held-out 上做 heuristic vs learned，对论文 claim 才真正有帮助。否则继续扩 query 数量，得到的也只会是更多 latent grounding，而不是更强的 headline 证据。
